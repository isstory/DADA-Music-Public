# 프롬프트 모음 — DADA Music은 이렇게 만들어졌습니다

이 프로젝트는 개발자가 코드를 직접 짜지 않고, **AI 코딩 도구(Claude Code)와 대화하며** 만들었습니다. 원래 주인이 AI에게 한 말을 순서대로 정리했습니다. 비슷한 앱을 만들거나 이 앱을 고칠 때 그대로, 또는 조금 바꿔서 쓰면 됩니다.

- 계정 이메일·ID·인증 코드 같은 개인정보는 `<…>`로 바꿨습니다.
- **굵은 글씨**는 원래 프롬프트, 그 아래는 AI가 한 일과 결과입니다.
- 처음에 준 기획서 원문은 [prompts/00_초기_기획서_원문.md](prompts/00_초기_기획서_원문.md)에 있습니다.

| 단계 | 사람이 한 말 (요약) | 결과 |
|---|---|---|

| 기초 기능 | "네. 진행" / "알아서 해주세요" | 로그인·검색·좋아요·플레이리스트, 자동 검증 |

| 보안·공유 | "보안 테스트 해줘", "깃허브에 올려줘" | 보안 점검, 기획서·가이드·공개 저장소 |

## 2. 단계별 원래 프롬프트

### 2.1 기획 검토
**(기획서 파일 첨부) 검토해줘. 디자인은 고급스럽게 할 거야. 스킬도 추천해줘**
- 기획서의 빠진 위험을 짚어 줬다.
  - YouTube 할당량은 계정이 아니라 프로젝트 전체에 걸린다.
  - 검색 1회가 100으로 비싸다.
  - 화면을 끈 재생은 공식 앱만 가능하다.
- 동기화 전략을 비교하고 디자인 방향을 제안했다.

**일단 2명 사용. 순차적으로 작업 진행**
- 코드 없이 휴대폰으로 확인하는 1단계 검증과, API로 재생목록을 만드는 검증 스크립트를 준비했다.

### 2.2 기술 검증 (Gate 0)
**1. 성공 2. 이건 꼭 로그인 해야 됨? 그 계정에 대한 관리를 해야 돼서 그러는 건가?**
- 재생목록을 만들려면 그 계정의 동의가 필요한 이유를 설명했다.
- 계정 하나만 연결하고 다른 사람은 링크로 듣는 구조를 제안했다.

**<할당량 확인 결과>는 10,000이다. 그리고 OAuth는 설정했고, 이 내용은 절대 커밋하지 말 것.**
- 비밀 파일을 깃에서 제외하고, 커밋 차단 장치를 추가했다.
- 이 규칙을 기억해 다음 작업에도 적용했다.

**OK. Coldplay 1번으로 왔고, 따봉 누름**
- 순서 변경이 앱에 반영되는 것과, YouTube Music 좋아요를 API로 읽을 수 있는 것을 확인했다.

**귀찮아. 네가 테스트해.**
- 서버에서 확인할 수 있는 것은 AI가 직접 검증하고, 휴대폰으로만 볼 수 있는 것은 "미검증"으로 남겼다.

> 💡 사람이 직접 하기 귀찮은 테스트는 이렇게 맡겨도 됩니다. AI는 확인할 수 있는 것과 없는 것을 구분해 알려 줍니다.

### 2.3 디자인
**네** (디자인 시스템부터 만들자는 제안에)
- 색·글꼴·화면 시안을 웹페이지로 만들고, 포인트 색을 바꿔 볼 수 있게 했다.

**1. 샴페인 2. 현대적인 고딕 위주 (보기 힘든 폰트는 싫어요.) 3. 그냥 스포티파이를 벤치마킹 해줬으면 하는데. PC와 모바일 모두**
- 시안 2판을 만들었다.
- Spotify형 배치를 따르되 초록색 같은 브랜드 요소는 쓰지 않았다.
- 하단 바는 재생바가 아니라 동기화 상태로 정직하게 표시했다.

> 💡 선택지를 받으면 번호로 짧게 답해도 충분합니다.

### 2.4 구조 결정
**앱으로 할 거야? GAS로 하면 어떨지?**
- 화면까지 GAS로 만들면 느리고, 홈 화면 설치가 안 되고, 경고 배너가 뜬다는 단점을 설명했다.
- **화면은 PWA, 서버는 GAS**로 나누는 안을 추천했다.

**네. 진행**
- 서버(GAS), 화면(React), 데모 모드를 만들고 스크린샷으로 직접 확인했다.

### 2.5 연결과 배포
**GAS의 스크립트 ID: <스크립트 ID>. 알아서 해주세요.**
- 업로드 도구로 연결했다. 회사 계정과 개인 계정 로그인이 섞이지 않도록 별도 프로필을 썼다.
- 원격 코드를 먼저 확인한 뒤 덮어썼다.
- 편집기에서 손으로 할 단계를 줄였다(설정은 파일로, DB는 자동 생성).

**B 계정은 일단 지금은 패스**

**(화면의 오류 문구 복사) 이건 뭐죠** → **좀 친절하게 방법을 알려줄래? 어디로 가라고?** → **(화면 캡처) 이게 어딨어 안 보여**
- 클릭 위치를 단계별로 안내했고, 캡처를 보고 바로 다음 클릭을 짚어 줬다.

> 💡 콘솔 화면에서 헤매면 **캡처를 붙여넣는 것**이 가장 빠릅니다.

**잘 나오는데**
- 로그인이 된 뒤에는 검색·좋아요·플레이리스트를 사람이 누르는 대신, 서버 자가 진단으로 자동 검증했다(9/9).

### 2.6 YouTube Music으로 보내기
**네, 아직은 127.0.0.1인데, 조금 뒤면 핸드폰에서도 가능하게 조정 가능하죠?**
- 보내기 기능을 만들고, 실제 YouTube에서 7개 시나리오로 자동 검증했다.
- 그 과정에서 결함 3개를 찾아 고쳤다.

### 2.7 AI 라디오 (핵심 기능)
**즐겨찾기 이건 쓸지 모르겠네. 그냥 이건 이렇게 두자. 내가 원하는 건 AI 라디오야. 좋아하는 노래들을 등록하고, 국내/해외/국내+해외로 선택하면 비슷한 음악을 구성하고, 플레이리스트로 만들어줍니다. 난 이걸 그냥 듣고 싶은 거야.**
- Gemini 추천 → YouTube 실제 곡 확인(지어낸 곡 제거) → 라디오 목록 → YouTube Music까지 버튼 하나로 이어지게 만들었다.

**넣었어. 반드시 git에서는 제외할 수 있도록.** (API 키를 파일에 직접 넣은 뒤)
- 키가 들어 있는지 값을 보지 않고 확인했다. 깃 제외와 커밋 차단 장치를 강화한 뒤 실제 라디오를 만들어 검증했다(20곡 모두 실재 곡).

> 💡 키는 채팅에 붙여넣지 말고 **파일에 직접 넣은 뒤 "넣었어"**라고만 말하세요.

### 2.8 휴대폰
**휴대폰으로 진행 가자.**
- 무료 HTTPS 호스팅(Firebase)에 올렸다.

**휴대폰에서 사파리로 구글 로그인하면, 하얀 화면에서 멈춤**
- iOS에서 팝업 로그인이 막히는 문제라서 페이지 이동 방식으로 바꿨다.

**재생하면 유튜브 뮤직까지 와서 이렇게 나오고 안 됩니다. "문제가 발생했습니다…"**
- 서버에서 실제 재생목록 상태를 진단했다(목록·곡은 정상).
- 비공개 목록 문제로 판단하고 일부 공개 전환을 제안했다.

**일부 공개로 바꿔도 됨**
- 공개 범위를 넓히는 일이라 AI가 먼저 승인을 받은 뒤 진행했다.

**액세스 차단 됨** → **저 계정도 접속 가능하게 추가 안 돼?** → **했는데도 계속 액세스 차단이네** → **저장했어**
- AI가 Google에 직접 요청을 보내 `redirect_uri_mismatch`를 확인하고, 어느 칸에 무엇을 넣을지 그림으로 안내했다.
- 저장 후 다시 확인해 해결됐음을 알렸다.

> 💡 "안 돼"만 말해도 AI가 원인을 직접 확인합니다. 화면 문구를 그대로 붙여넣으면 더 빠릅니다.

### 2.9 마무리
**일단 오케이 됐다. 커밋해줘. 보안적인 부분은 다 보호해줘**
- 커밋할 파일 전체에서 키·ID·이메일을 검사한 뒤 커밋했다.

**이게 근데 왜 자꾸 로그인이 풀릴까?**
- 원인은 Google 토큰의 1시간 만료였다. 서버가 발급하는 30일 세션으로 바꿨다.

**배포**

**보안적인 API key 등은 제거하고, 보안 테스트를 해주세요. 완료되면 내 깃허브 계정에 DADA Music이라는 폴더를 만들고 올려주세요.**
- 서버 취약점 8개를 고쳤고, 공격 시험 13개가 모두 막혔다.
- 커밋 작성자 이메일을 GitHub 비공개 주소로 바꾼 뒤 비공개 저장소에 올렸다.

**지인에게 공유하려고 합니다. 기획서와 프로젝트 압축 파일, 지인 PC에 구현해서 AI로 조정할 수 있는 상세 가이드를 주세요.**

**압축 파일은 회사 메신저 보안에 걸리네요. 깃허브에 DADA-Music-Public이라는 폴더를 만들고 공개로 올려주세요. 가이드와 프롬프트도 정리해 주세요.**
- 이 저장소가 그 결과입니다.

## 4. AI와 일할 때 도움이 됐던 방식
1. **목표를 사람의 말로 말하기:** "AI 라디오를 그냥 듣고 싶어"처럼 원하는 경험을 말하면, AI가 필요한 기능을 쪼개서 만듭니다.
2. **순차 진행 + 검증 기록:** 단계마다 PASS/FAIL을 남기면 어디까지 됐는지 헷갈리지 않습니다.
3. **선택지는 번호로 답하기:** "1. 샴페인 2. 고딕 3. Spotify"처럼 짧게 답해도 충분합니다.
4. **귀찮은 확인은 맡기기:** AI는 서버 쪽은 직접 검증하고, 사람만 볼 수 있는 것(휴대폰 화면 등)은 따로 표시합니다.
5. **막히면 캡처나 오류 문구 그대로:** 설명보다 화면 하나가 빠릅니다.
6. **비밀값은 직접:** 키는 파일에 직접 넣고, 브라우저 로그인·콘솔 클릭은 사람이 합니다. AI는 위치를 안내합니다.
7. **공개 범위나 삭제는 AI가 먼저 묻습니다:** 재생목록 공개 전환처럼 되돌리기 어려운 일은 승인을 받고 진행합니다.
