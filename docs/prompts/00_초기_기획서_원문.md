# DADA Music — Claude Code 개발 기획서 v1.0

작성일: 2026-11-09
프로젝트: N명이 사용하는 Spotify 스타일 AI 음악 탐색·추천·관리 서비스

## 0. Claude Code에 전달할 최상위 지시

당신은 시니어 제품 기획자, UX/UI 디자이너, 프론트엔드·백엔드 엔지니어, YouTube API 통합 전문가, QA 담당자로 협업한다. 아래 요구사항을 읽고 **기술적 제약을 먼저 검증한 후** 실제 동작하는 MVP를 단계별로 개발한다. 실제 API 연동 수준과 시연 범위를 보고한다. 구현 가능성/제약/검증 필요 항목을 구분하고, 각 단계의 실행 방법과 테스트 결과를 제시한다. UI는 고품질 상용 음악 앱 수준을 목표로 하되 브랜드 고유의 디자인 방향을 제안한다.

**기술 검토 항목:** YouTube Music Premium, 공식 API, 앱 간 연동, 백그라운드 재생의 지원 범위와 정책을 Claude에서 독립적으로 재검토하고 대안을 비교한다.

## 1. 제품 비전

- 이름(가칭): **DADA Music**
- 대상: N명 사용자. 개인별 취향·좋아요·플레이리스트와 사용자 간 공유 플레이리스트 지원.
- 핵심 가치: 국가·시대·장르별 음악을 탐색하고, 개인의 선호를 학습하여 AI 라디오/추천곡을 생성하고, YouTube Music 공식 앱에서 음악을 듣는다.
- 최우선 사용자 경험: 휴대폰 화면을 꺼도 음악이 계속 들려야 한다. 이 기능은 **YouTube Music 공식 앱 및 적절한 구독 조건**에 의존한다.
- 사용 환경: 모바일 우선, 데스크톱에서도 사용. 개발 환경은 Windows + VS Code + Claude Code/Codex.

## 2. 범위 및 우선순위

### P0 — 반드시 구현할 MVP
1. Google OAuth 로그인, N명 사용자 계정 분리 및 데이터 접근 제어.
2. 고품질 반응형 다크 테마 UI: 홈, 탐색, 차트, AI 라디오, 라이브러리, 플레이리스트, 설정.
3. YouTube Data API 기반 곡/아티스트 검색과 메타데이터 표시. 검색 결과가 일반 영상·라이브·커버일 수 있으므로 음악 식별 품질 관리.
4. 좋아요/싫어요 또는 관심 없음, 즐겨찾기, 개인 플레이리스트 생성·편집·삭제·정렬.
5. 사용자가 선호 곡/아티스트/장르/시대를 직접 등록하고 AI 추천 리스트를 생성·저장.
6. YouTube 계정에 **DADA Music 전용 고유 플레이리스트**를 생성하고, DADA Music의 선택 목록을 동기화.
7. 동기화한 재생목록을 YouTube Music 공식 앱/웹에서 열기. 사용자가 재생을 시작하면 공식 앱이 다음 곡 및 백그라운드 재생을 담당.
8. 실제 기기에서 재생목록 연속 재생·화면 OFF 재생 검증. 지원 여부와 검증 결과를 기록.

### P1 — 콘텐츠 확장
- 국가별 인기 음악 차트: 데이터 소스와 국가·갱신일·순위 산정 기준을 명시.
- 시대별 차트: 1980/1990/2000/2010/2020년대. 당시 역사적 차트와 현재 인기를 명확히 구분.
- 장르별 추천: K-POP, J-POP, 힙합, 록, 발라드, 팝 등.
- 공개 인기 플레이리스트 탐색. API에서 실제로 접근 가능한 공개 목록만 표시.
- N명 취향 믹스, 분위기별 추천, 숨은 명곡 발견.

### P2 — 고도화
- 개인 취향 DNA 및 추천 이유 설명.
- 개인화된 AI 라디오 재생목록 자동 갱신(할당량과 사용자 승인 정책 준수).
- 청취 통계: **DADA Music에서 실제 관측 가능한 이벤트만** 집계. YouTube Music 공식 앱의 재생 시간, 건너뛰기, 좋아요 이벤트를 수집 가능 범위를 조사.
- 플레이리스트 동기화 상태, 실패 재시도, 중복 곡 감지, 충돌 처리.

## 3. 핵심 UX 시나리오

### 시나리오 A: AI 라디오 30곡 재생
1. 사용자가 DADA Music에서 '나만의 AI 라디오'를 선택한다.
2. AI가 30곡을 추천하고 추천 이유를 보여준다.
3. 사용자가 곡을 검토하고 'YouTube Music에서 듣기'를 누른다.
4. 서버가 로그인된 사용자의 YouTube 계정에서 전용 플레이리스트 ID를 조회한다. 없으면 한 번 생성한다.
5. 해당 플레이리스트에 목표 곡과 순서를 동기화한다.
6. 동기화 성공을 확인한 뒤 재생목록 링크를 열거나 복사하도록 한다.
7. 사용자가 YouTube Music에서 해당 재생목록을 재생한다.
8. 이후의 연속 재생·잠금화면 재생은 YouTube Music 공식 앱이 담당한다.

**기술 검토:** 외부 앱에서 YouTube Music으로 전달 가능한 명령, 자동 재생 시작 여부, 추가 사용자 조작 필요성을 조사한다.

### 시나리오 B: 한 곡 듣기
- 곡의 적절한 YouTube Music URL(예: `https://music.youtube.com/watch?v=VIDEO_ID`)을 열어 공식 앱/웹에서 듣는다.
- 이 방식의 다음 곡 처리 및 YouTube Music 대기열 동작을 확인한다.

### 시나리오 C: 좋아요와 추천
- DADA Music에서 누른 하트는 DADA Music 데이터베이스에 기록하고 AI 추천에 반영한다.
- YouTube Music 앱의 하트 데이터 연동 가능 범위를 검토한다.
- 사용자가 직접 등록한 선호 곡과 DADA Music에서 발생한 상호작용으로 추천을 개선한다.

## 4. 전용 플레이리스트 동기화 전략

### 4.1 식별
- YouTube 계정별 전용 재생목록 1개 이상을 생성한다.
- 예시 이름: `DADA_MUSIC_PLAYER_<USER_SHORT_ID>`.
- **이름이 아니라 YouTube playlistId를 영속 저장**한다. 이름 중복 가능성에 의존하지 않는다.
- N명이 같은 YouTube 계정을 쓰는 경우 동시 재생·목록 충돌·구독 제한 문제가 발생할 수 있으므로, 원칙적으로 개인별 Google/YouTube 계정 연결을 권장한다.

### 4.2 동기화
- 사용자가 제안한 기본 아이디어: 재생할 때 전용 플레이리스트의 기존 곡을 지우고 새로운 곡을 넣는다.
- 전체 삭제/재삽입과 변경분(diff) 동기화의 API 비용, 구현 난이도, 일관성을 비교한다.
- 요구 순서 보장: 항목 추가 순서 및 필요시 position 업데이트를 테스트한다.
- 중복 제거 정책, 접근 불가능한 영상 처리, 일부 실패 시 롤백 또는 복구, 동기화 중 이중 클릭 방지, 사용자별 동시 실행 잠금 구현.
- 동기화 진행 상태를 표시하고, 실패 시 사용자가 기존 재생목록을 계속 사용할 수 있도록 안전하게 처리한다.
- 동기화가 끝난 뒤 **실제 YouTube 측 재생목록 조회 결과를 검증**한다.
- 재생 중 목록 수정 시 대기열 반영 시점을 확인한다. 새 목록을 다시 열도록 안내한다.

### 4.3 할당량
- 기본 YouTube Data API 프로젝트 할당량은 일반적으로 일 10,000 units 수준이지만 프로젝트별 실제 값은 확인한다.
- `playlistItems.insert`, `playlistItems.delete`는 각각 통상 50 units/호출이므로 30곡 전체 교체 시 60회 호출 ≈ 3,000 units(기타 조회/검색 비용 제외).
- 30곡 전체 교체를 자주 반복하면 빠르게 소진된다. 곡이 동일하면 동기화를 생략하고, 변경분만 처리하며, 사용량/잔여량을 관리자 화면에 표시한다.
- API 할당량 운영 정책과 최적화 방안을 검토한다.

## 5. 재생 기술 검토 항목

| 접근 | 기대 기능 | Claude 재검토 항목 |
|---|---|---|
| YouTube Music 곡 링크 열기 | 공식 앱/웹에서 해당 곡 열기 | 다음 곡 원격 제어 지원 여부 |
| YouTube Data API 플레이리스트 | 생성·조회·항목 추가·삭제·일부 수정 | 재생 기능과의 연결 방식 |
| YouTube IFrame Player API | 앱 화면이 활성화된 상태에서 영상 로딩·종료 이벤트 기반 다음 곡 재생 | 공식 앱 제어 및 화면 OFF 재생 지원 범위 |
| YouTube Music Premium | 공식 앱에서 지원 조건하에 백그라운드 재생 | 제3자 앱 연동 권한 확인 |

- **YouTube Music에서 API로 만든 재생목록이 실제 표시되는지, 음악 전용 트랙으로 정상 인식되는지, 순서대로 연속 재생되는지** 실제 계정·기기에서 PoC로 확인한다.
- 공식·비공식 연동 방식의 기술성, 안정성, 서비스 정책 및 법적 리스크를 비교 검토한다.
- 음원 이용 권한과 관련 정책을 검토 항목으로 둔다.

## 6. 권장 기술 스택

- 프론트엔드: React + TypeScript + Vite 또는 Next.js(배포·서버 기능에 따라 선택).
- 스타일: Tailwind CSS + 고품질 컴포넌트 시스템, 모바일 퍼스트, 접근성 및 다크 테마.
- 백엔드: Firebase Authentication, Firestore, Cloud Functions(또는 Cloud Run).
- AI: Gemini API. 추천은 추천 후보 곡의 실제 YouTube ID 확인 방식을 설계한다.
- 외부 음악 메타데이터: YouTube Data API v3, 합법적·공식 차트 데이터 소스.
- 보조 자동화: GAS는 선택 사항. 메인 프론트엔드 및 재생 기능에 대한 적합성을 비교한다.
- 비밀키/토큰: 서버 측 보관, 최소 OAuth scope, 사용자별 격리, 토큰 암호화, 로그 민감정보 마스킹.
- 운영: API quota 관측, 오류 추적, 재시도/백오프, 비용 상한.

## 7. 데이터 모델 초안

- `users`: uid, displayName, linkedGoogleAccount, createdAt, settings
- `tracks`: youtubeVideoId, title, artist, thumbnail, duration, source, availabilityCheckedAt
- `likes`: uid, trackId, reaction, createdAt
- `playlists`: id, ownerUid, title, visibility, kind, createdAt, updatedAt
- `playlist_items`: playlistId, trackId, position, addedAt
- `youtube_sync`: uid, internalPlaylistId, youtubePlaylistId, lastSyncedHash, lastSyncedAt, status, error
- `recommendation_runs`: id, uid, inputSignals, recommendedTrackIds, explanations, modelVersion, createdAt
- `shared_playlists`: playlistId, memberUids, permissions

실제 구현 시 Firestore에 맞게 문서/서브컬렉션 구조와 인덱스를 최적화한다. 개인정보·OAuth 토큰을 일반 사용자 조회 가능한 컬렉션에 저장 시 암호화 및 접근 제어 방식을 검토한다.

## 8. 화면 및 디자인 요구사항

1. **Home**: 인사, 최근 플레이리스트, 오늘의 AI 추천, 국가별 TOP, 시대별 인기, N명 취향 믹스.
2. **Discover**: 검색, 국가·시대·장르 필터, 인기 플레이리스트, 추천 이유.
3. **AI Radio**: 취향 입력, 유사도/새로움 비율, 추천 30곡, 하트, 목록 편집, YouTube Music에서 듣기.
4. **Library**: 좋아요한 곡, 내 플레이리스트, 공유 플레이리스트, 아티스트.
5. **Playlist Detail**: 커버, 곡 순서 변경, 중복 제거, 동기화 상태, 공식 앱 열기.
6. **Settings**: Google 계정 연결, 권한, 개인화 설정, 데이터 삭제, API 동기화 상태.

디자인 원칙:
- 상용 음악 앱 수준의 타이포그래피·여백·앨범아트·애니메이션·로딩/빈 화면/오류 상태.
- 모바일에서 엄지로 조작하기 쉬운 하단 내비게이션.
- DADA Music 고유의 브랜드 디자인 방향 수립.
- 재생바의 실제 기능과 상태 표현 방식을 설계한다. 하단 재생바를 만든다면 'YouTube Music에서 듣기' 등 실제 기능을 정확히 표현한다.
- 디자인팀과 UX팀의 검토를 매 단계 필수로 수행한다.

## 9. 개발 순서와 게이트

### Gate 0 — 기술 PoC (최우선, 다른 화면 개발보다 먼저)
- OAuth 인증 및 YouTube Data API 권한 확보.
- 테스트용 5곡 플레이리스트 생성 및 곡 추가.
- YouTube Music 모바일 앱에서 실제로 목록을 찾고 여는지 확인.
- 첫 곡 시작 후 다음 곡이 DADA Music 순서대로 재생되는지 확인.
- 아이폰/안드로이드 중 실제 사용 기기에서 화면 OFF 연속 재생 확인.
- 동일 기기에서 웹앱 → YouTube Music 앱 전환 흐름 확인.
- 재생 중 목록 교체 시 대기열 동작 확인.
- 테스트 결과를 PASS/FAIL/UNVERIFIED로 기록하고 증거를 남긴다.
- **Gate 0 결과에 따라 구현 대안과 다음 단계 계획을 제시한다.**

### Gate 1 — 제품 기초
- 인증, 데이터 모델, 기본 UI, 음악 검색, 좋아요, 개인 플레이리스트.

### Gate 2 — 추천
- 취향 프로필, Gemini 추천, 실제 곡 ID 검증, AI 라디오 목록 생성.

### Gate 3 — 동기화
- 전용 재생목록 ID 관리, diff 동기화, 상태 표시, 공식 앱 열기, 오류/할당량 대응.

### Gate 4 — 콘텐츠 및 다중 사용자 기능
- 국가별/시대별/장르별 목록, 공동 플레이리스트, 개인화 고도화.

### Gate 5 — QA·배포
- 실제 모바일 테스트, 권한·보안·비용 점검, 접근성, 반응형, 배포 문서.

## 10. 테스트 및 완료 기준

- 사용자가 실제 Google 계정으로 로그인 가능.
- N명 사용자의 데이터 접근 권한과 분리 상태 검증.
- 검색 결과의 YouTube ID가 실제로 유효하며 열림.
- 좋아요/플레이리스트 변경 사항이 새로고침 후에도 유지.
- AI가 추천한 곡이 실제 검색·검증된 곡이며 추천 근거가 표시됨.
- 전용 YouTube playlistId가 중복 생성 없이 유지됨.
- 동기화 후 YouTube에서 실제 목록과 순서를 확인 가능.
- 할당량 초과·권한 거부·삭제된 영상·중복 클릭·네트워크 오류에 대응.
- YouTube Music 화면 OFF 재생은 실제 기기 테스트로 확인된 경우에만 PASS.
- 데모 데이터와 실제 API 데이터는 화면과 보고서에서 명확히 구분.
