# DADA Music 기획서

> 좋아하는 노래 몇 곡을 고르면 AI가 비슷한 곡으로 라디오를 만들어 YouTube Music 재생목록으로 보내 주는 개인용 음악 앱

버전 0.1 · 2026-11 · 개인 프로젝트 (사용자 1~2명)

---

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 무엇을 하나 | 좋아하는 노래 + 국내/해외 선택 → AI가 비슷한 곡 20~30곡 추천 → 실제 YouTube 곡인지 확인 → YouTube Music 재생목록 생성 → 휴대폰에서 바로 재생 |
| 누가 쓰나 | 본인과 지인 1명 (허용한 Google 계정만 로그인 가능) |
| 재생은 어디서 | **YouTube Music 공식 앱**. DADA는 음악을 직접 재생하지 않는다 |
| 어디서 쓰나 | 휴대폰(홈 화면에 설치하는 웹앱, PWA)과 PC 브라우저 |
| 운영 비용 | 0원 (Google·Firebase 무료 범위). 화면을 끈 재생은 YouTube Premium 필요 |

### 왜 재생을 YouTube Music에 맡기나
- 화면을 꺼도 음악이 계속 나와야 한다는 것이 최우선 요구였다.
- 웹앱에서 YouTube 영상을 몰래 소리만 재생하는 것은 YouTube 정책 위반이고 기술적으로도 불안정하다.
- 공식 YouTube Data API로 **재생목록을 만들어 넣는 것**은 허용된다. 그 목록을 공식 앱이 재생하면 백그라운드 재생, 잠금 화면 조작, 다음 곡 넘김이 모두 공식 기능으로 해결된다.
- 이 구조가 실제로 되는지 개발 전에 먼저 검증했다(Gate 0, 4장).

## 2. 핵심 기능

### 2.1 AI 라디오 (메인 기능)
1. **좋아하는 노래 등록:** 검색해서 추가하거나, 좋아요한 곡을 한 번에 가져온다(최대 20곡). 저장되어 다음에도 남는다.
2. **어떤 음악으로:** 국내 / 해외 / 국내+해외, 20곡 / 30곡
3. **「AI 라디오 만들고 듣기」** 한 번으로 아래가 자동으로 이어진다.
   - Gemini가 목표보다 8곡 많이 추천 (곡마다 추천 이유 포함)
   - 서버가 곡마다 YouTube를 검색해 **제목이 맞는 실제 곡만 채택** (AI가 지어낸 곡 제거)
   - 사용자별 라디오 플레이리스트 1개를 새 곡으로 교체
   - YouTube Music 재생목록으로 보내고 「YouTube Music에서 듣기」 버튼 표시
- 등록한 노래와 「관심 없음」을 누른 곡은 추천에서 제외한다.
- 실제 결과 예: 아이유 「밤편지」 + Coldplay 「Viva La Vida」, 국내+해외 20곡 → 20곡 모두 실재 곡 확인, 국내 10 / 해외 10, 약 46초

### 2.2 YouTube Music으로 보내기 (동기화)
| 상황 | 동작 | YouTube 사용량 |
|---|---|---|
| 지난번 보낸 것과 같음 | 그대로 둠 | 약 1 |
| 뒤에 곡만 추가됨 | 추가된 곡만 넣음 | 곡당 50 |
| 순서 변경·곡 삭제 등 | 새 목록 생성 → 순서대로 넣기 → 실제로 다시 조회해 순서 확인 → 통과하면 교체, 이전 목록 삭제 | 30곡 약 1,600 |

- 확인에 실패하면 이전 목록을 그대로 둔다(듣던 목록이 깨지지 않음).
- 목록은 **일부 공개**(링크로만 열림)로 만든다. 비공개로 하면 휴대폰 YouTube Music 앱의 로그인 계정이 다를 때 열리지 않는 문제가 있었다.
- 「듣기」 링크는 목록 페이지가 아니라 첫 곡부터 바로 재생하는 형식이다.

### 2.3 라이브러리
- 곡 검색 (공식 음원을 먼저 보여 줌, 검색은 Enter 시에만 실행)
- 좋아요 / 관심 없음
- 플레이리스트 만들기·이름 변경·삭제·순서 편집·곡 빼기 (중복 곡 자동 차단)
- 한국 인기 뮤직비디오 (출처·기준일 표시, "공식 음원 차트 아님" 명시)
- 곡 제목을 누르면 YouTube Music에서 그 곡이 열린다

## 3. 시스템 구조

```
[휴대폰 / PC 브라우저]
   web/  React PWA  ──(HTTPS, 세션 토큰)──▶  gas/  Google Apps Script 웹앱
   Firebase Hosting                               │  (계정 A 권한으로 실행)
        │                                         ├─▶ Google 시트 (DB)
        │ Google 로그인 (최초 1회)                 ├─▶ YouTube Data API v3 (검색·재생목록)
        ▼                                         └─▶ Gemini API (추천)
   accounts.google.com
                                     YouTube Music 앱 ◀── 재생목록 링크
```

| 구성 | 기술 | 선택 이유 |
|---|---|---|
| 화면 | React 18 + TypeScript + Vite, PWA | 빠른 화면, 홈 화면 설치, 무료 정적 호스팅 |
| 서버 | Google Apps Script (clasp로 관리) | 무료, 서버 관리 없음, 계정 A의 YouTube 권한을 그대로 사용 (토큰 저장·갱신 코드 불필요) |
| DB | Google 시트 | 2인 규모에 충분, 데이터를 눈으로 확인 가능 |
| AI | Gemini (기본 gemini-2.5-flash), JSON 스키마 응답 | 무료 범위, 구조화된 응답 |
| 호스팅 | Firebase Hosting | 무료 HTTPS (휴대폰 Google 로그인에 필요) |

### 3.1 화면을 GAS로 만들지 않은 이유
GAS로 화면까지 만들면 요청마다 1~3초가 걸리고, 홈 화면 설치가 안 되며, 다른 사용자에게 Google 경고 배너가 뜬다. 그래서 **화면은 PWA, 서버만 GAS**로 나눴다.

### 3.2 로그인 구조
1. Google 로그인(OpenID Connect, **페이지 이동 방식**) — 팝업 방식은 iOS Safari·홈 화면 앱에서 하얀 화면으로 멈춰서 바꿨다.
2. 서버가 Google ID 토큰을 검증(우리 앱용인지, 이메일 인증, 허용 목록) → **30일 세션** 발급
3. 이후 모든 요청은 세션으로. 쓰는 동안 자동 연장. 서버에는 세션의 해시만 저장.
- 처음에는 Google 토큰(1시간)을 그대로 써서 매시간 로그인이 풀렸고, 세션 방식으로 해결했다.

### 3.3 서버 API (요청 이름 → 기능)
| 분류 | 요청 |
|---|---|
| 로그인 | `auth.session`, `auth.logout`, `me` |
| 곡 | `search`, `chart`, `reactions.set`, `reactions.list` |
| 플레이리스트 | `playlists.list/get/create/update/delete/addTracks/removeTracks/reorder` |
| 보내기 | `sync.push` |
| 라디오 | `radio.get`, `radio.save`, `radio.generate` |

### 3.4 데이터 (Google 시트의 탭)
| 탭 | 내용 |
|---|---|
| `users` | 로그인한 사용자 |
| `tracks` | 곡 정보 캐시 (모든 사용자 공용) |
| `search_cache` | 검색 결과 캐시 (7일) — 같은 검색어에 할당량을 다시 쓰지 않음 |
| `reactions` | 좋아요 / 관심 없음 |
| `playlists`, `playlist_items` | 플레이리스트와 곡 순서 |
| `youtube_sync` | 플레이리스트 ↔ YouTube 재생목록 연결, 보낸 곡, 제외된 곡 |
| `radio_profiles`, `radio_reasons` | 라디오 설정(좋아하는 노래·지역·곡 수), 곡별 추천 이유 |

## 4. 개발 과정 (Gate)

| Gate | 내용 | 결과 |
|---|---|---|
| 0 기술 검증 | API로 만든 재생목록이 YouTube Music 앱에 보이고, 순서대로, 화면을 꺼도 재생되는가 | ✅ 통과 |
| 1 기초 | 로그인, DB, 검색, 좋아요, 플레이리스트 | ✅ 통과 (자동 검증 9/9) |
| 2 AI 라디오 | Gemini 추천 → 실제 곡 확인 → 라디오 | ✅ 통과 (5/5) |
| 3 동기화 | YouTube Music으로 보내기 | ✅ 통과 (7/7) |
| 보안 | 비밀값 관리, 서버 강화, 보안 헤더 | ✅ 공격 시험 13개 차단 — [SECURITY.md](SECURITY.md) |

### 검증하며 알게 된 것 (설계에 반영됨)
1. YouTube 재생목록은 수정 직후 몇 초 동안 예전 상태가 조회된다 → 확인할 때 2·4·8초 간격으로 다시 조회
2. 같은 목록에 곡을 빠르게 연속으로 넣으면 YouTube가 가끔 거부한다(409) → 1·2·4초 간격 재시도
3. 검색만으로 곡을 고르면 라이브·커버·방송 무대 영상이 섞인다 → 공식 음원(Topic 채널) 가점, 라이브·방송 감점 규칙
4. 비공개 재생목록은 휴대폰 앱 계정이 다르면 열리지 않는다 → 일부 공개
5. YouTube Music 앱에서 누른 좋아요는 API로 읽을 수 있다 (추후 추천에 활용 가능)
6. 앱이 YouTube Music을 원격 조종(재생 시작·다음 곡)하는 공식 방법은 없다 → 링크로 열고 재생은 앱에 맡긴다

## 6. 제약과 비용

### YouTube 할당량 (하루 10,000, 한국 시간 오후 4~5시 초기화)
| 작업 | 사용량 |
|---|---|
| 검색 1회 | 100 (같은 검색어 7일 캐시) |
| 곡 정보 조회 | 50곡당 1 |
| 재생목록 만들기 / 곡 넣기 / 삭제 | 각 50 |
| **AI 라디오 1회 (20곡, 처음 보는 곡들)** | **약 3,200** → 하루 약 3회. 쓸수록 캐시로 감소 |

할당량은 Google에 무료로 증설 신청을 할 수 있다(심사 필요).

### 그 밖의 제약
- 화면을 끈 재생은 YouTube Premium(또는 YouTube Music Premium)이 필요하다.
- Google OAuth 앱이 "테스트" 상태라 로그인 시 "확인되지 않은 앱" 경고가 뜨고, 테스트 사용자로 등록한 계정만 로그인할 수 있다.
- 재생목록은 서버를 실행하는 Google 계정(계정 A)의 YouTube에 만들어진다. 다른 사용자도 링크로 들을 수 있다.
- YouTube 재생 기록·건너뛰기 정보는 API로 받을 수 없다.
